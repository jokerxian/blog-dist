Vue 3 响应式原理 ​

Vue 3 把响应式从 Object.defineProperty 换成了 Proxy，好处是能拦截新增属性、数组索引和 delete。

一、三个角色 ​

副作用函数与依赖桶 ​

  • effect：需要被重复执行的函数；
  • track：执行时记录「谁依赖了这个属性」；
  • trigger：属性变化时把相关副作用重新跑一遍。
js
const targetMap = new WeakMap()

function track(target, key) {
  let depsMap = targetMap.get(target)
  if (!depsMap) targetMap.set(target, (depsMap = new Map()))
  let dep = depsMap.get(key)
  if (!dep) depsMap.set(key, (dep = new Set()))
  if (activeEffect) dep.add(activeEffect)
}

function trigger(target, key) {
  const depsMap = targetMap.get(target)
  if (!depsMap) return
  const dep = depsMap.get(key)
  if (dep) dep.forEach((effect) => effect())
}

Proxy 拦截 ​

get 里调用 track，set 里先改值再调用 trigger。嵌套对象在 get 时递归包一层 reactive，用到哪层代理哪层。

二、为什么不直接遍历 ​

Object.defineProperty 需要在初始化时递归遍历所有属性，对象一大就慢；Proxy 是惰性的，访问到才代理。

数组的处理 ​

Vue 3 不需要重写数组方法，push、splice 触发的是索引与 length 的 set，一样能收集依赖。

三、和渲染的关系 ​

组件渲染函数本身就是一个 effect。渲染时读了哪些响应式数据，就被记进依赖桶；数据变化时重新执行渲染函数，得到新的虚拟 DOM，再走 patch。

响应式负责「知道变了」，渲染器负责「只改该改的那一小块」，两者分开，才有了 Vue 3 的性能空间。
