Spring Security + JWT 认证实践 ​

Spring Security 从 6.x 开始正式移除了 WebSecurityConfigurerAdapter，网上大量基于 and() 链式调用的教程已经跑不通了。这篇按当前的方式梳理一套完整的 JWT 登录鉴权流程。

一、整体流程 ​

  1. 用户提交用户名密码，AuthenticationManager 调用 UserDetailsService 加载用户并比对密码；
  2. 认证通过后生成 JWT，把用户信息缓存到 Redis，key 形如 login:{userId}；
  3. 后续请求携带 Authorization: Bearer <token>；
  4. 自定义过滤器解析 token、从 Redis 取用户信息，写入 SecurityContext；
  5. 其余请求由 Spring Security 的授权规则决定放行或拦截。

无状态会话意味着服务端不存 Session，扩展多实例时不用考虑会话共享。

二、引入依赖 ​

xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>

<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-api</artifactId>
    <version>0.13.0</version>
</dependency>
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-impl</artifactId>
    <version>0.13.0</version>
    <scope>runtime</scope>
</dependency>
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-jackson</artifactId>
    <version>0.13.0</version>
    <scope>runtime</scope>
</dependency>

引入 starter 后，Spring Boot 会自动开启安全过滤链，所有接口默认都需要认证，直到你在配置里显式放行。

三、安全配置类 ​

java
@Configuration
@EnableWebSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtAuthenticationTokenFilter jwtAuthenticationTokenFilter;
    private final AuthenticationEntryPointImpl authenticationEntryPoint;

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
                // 前后端分离不使用 Session，CSRF 防护也就不需要了
                .csrf(AbstractHttpConfigurer::disable)
                .cors(cors -> cors.configurationSource(corsConfigurationSource()))
                .sessionManagement(session ->
                        session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
                .exceptionHandling(handling ->
                        handling.authenticationEntryPoint(authenticationEntryPoint))
                .authorizeHttpRequests(auth -> auth
                        // 登录、注册允许匿名访问
                        .requestMatchers("/users/login", "/users/register").permitAll()
                        // 其余请求一律需要认证
                        .anyRequest().authenticated())
                // 把 JWT 过滤器放到用户名密码过滤器之前
                .addFilterBefore(jwtAuthenticationTokenFilter, UsernamePasswordAuthenticationFilter.class);

        return http.build();
    }

    @Bean
    public AuthenticationManager authenticationManager(AuthenticationConfiguration configuration) throws Exception {
        return configuration.getAuthenticationManager();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public CorsConfigurationSource corsConfigurationSource() {
        CorsConfiguration configuration = new CorsConfiguration();
        configuration.setAllowedOriginPatterns(List.of("*"));
        configuration.setAllowedHeaders(List.of("*"));
        configuration.setAllowedMethods(List.of("*"));
        configuration.setAllowCredentials(true);

        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/**", configuration);
        return source;
    }
}

和旧写法的差别：

  • 不再继承 WebSecurityConfigurerAdapter，改为声明 SecurityFilterChain Bean；
  • 不再需要 AuthenticationManagerBuilder 手动绑定 UserDetailsService 和 PasswordEncoder，容器里各有一个 Bean 时 Spring Security 会自动装配；
  • antMatchers 改成了 requestMatchers；
  • anonymous() 表示「仅允许未登录访问」，permitAll() 表示「任何人都能访问」，登录注册接口通常用后者。

四、用户信息与 UserDetailsService ​

UserDetails 是 Spring Security 认知用户的方式，把业务里的 User 包一层：

java
@Data
@NoArgsConstructor
public class LoginUser implements UserDetails, Serializable {

    private User user;

    /** 字符串形式的权限，例如 "system:user:list" */
    private List<String> permissions;

    /** Spring Security 需要的权限对象，序列化时忽略，用到时再转换 */
    @JsonIgnore
    private List<GrantedAuthority> authorities;

    public LoginUser(User user, List<String> permissions) {
        this.user = user;
        this.permissions = permissions;
    }

    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        if (authorities == null) {
            authorities = permissions.stream()
                    .map(SimpleGrantedAuthority::new)
                    .collect(Collectors.toList());
        }
        return authorities;
    }

    @Override
    public String getPassword() {
        return user.getPassword();
    }

    @Override
    public String getUsername() {
        return user.getUsername();
    }

    @Override
    public boolean isAccountNonExpired() {
        return true;
    }

    @Override
    public boolean isAccountNonLocked() {
        return true;
    }

    @Override
    public boolean isCredentialsNonExpired() {
        return true;
    }

    @Override
    public boolean isEnabled() {
        return "0".equals(user.getStatus());
    }
}

isEnabled 顺手把账号状态接上，比无脑返回 true 更实用。

加载用户：

java
@Service
@RequiredArgsConstructor
public class UserDetailsServiceImpl implements UserDetailsService {

    private final UserMapper userMapper;
    private final PermissionMapper permissionMapper;

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        User user = userMapper.selectOne(
                new LambdaQueryWrapper<User>().eq(User::getUsername, username));
        if (user == null) {
            // 不要提示「用户不存在」，避免被用来枚举账号
            throw new UsernameNotFoundException("用户名或密码错误");
        }

        List<String> permissions = permissionMapper.selectPermsByUserId(user.getUserId());
        return new LoginUser(user, permissions);
    }
}

五、JWT 工具类 ​

jjwt 0.12 之后 API 改成了更明确的流式写法，setSubject、signWith(algorithm, key) 这些旧方法已经移除。同时 HS256 要求密钥至少 256 位，随便写七个字符会在签名时直接报错：

java
public final class JwtUtil {

    /** 至少 32 字节，生产环境放配置中心，不要硬编码 */
    private static final String JWT_SECRET = "change-me-to-a-random-32-bytes-secret";
    private static final SecretKey KEY =
            Keys.hmacShaKeyFor(JWT_SECRET.getBytes(StandardCharsets.UTF_8));

    private JwtUtil() {
    }

    public static String createJWT(String subject, Duration ttl) {
        Instant now = Instant.now();
        return Jwts.builder()
                .id(UUID.randomUUID().toString())
                .subject(subject)
                .issuer("admin")
                .issuedAt(Date.from(now))
                .expiration(Date.from(now.plus(ttl)))
                .signWith(KEY)
                .compact();
    }

    public static Claims parseJWT(String jwt) {
        return Jwts.parser()
                .verifyWith(KEY)
                .build()
                .parseSignedClaims(jwt)
                .getPayload();
    }
}

signWith(KEY) 会根据密钥长度自动选择算法，不用再显式传 SignatureAlgorithm。解析失败会抛 JwtException，包括签名不合法、已过期、格式错误等情况。

六、登录接口 ​

java
@PostMapping("/login")
public String login(@RequestBody LoginDTO dto) {
    Authentication authentication = authenticationManager.authenticate(
            new UsernamePasswordAuthenticationToken(dto.getUsername(), dto.getPassword()));

    LoginUser loginUser = (LoginUser) authentication.getPrincipal();
    String userId = loginUser.getUser().getUserId();

    // 管理员不过期，普通用户 7 天
    Duration ttl = "0".equals(loginUser.getUser().getUserType())
            ? Duration.ofDays(30)
            : Duration.ofDays(7);
    String token = JwtUtil.createJWT(userId, ttl);

    redisTemplate.opsForValue().set("login:" + userId, loginUser, ttl);
    return token;
}

密码比对由 DaoAuthenticationProvider 完成：它拿到 UserDetails 里加密后的密码，用 PasswordEncoder.matches 和用户输入比对，密码错误会抛 BadCredentialsException。所以数据库里存的必须是 BCrypt 密文，不能是明文。

把异常交给全局处理，避免把堆栈暴露给前端：

java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(AuthenticationException.class)
    @ResponseStatus(HttpStatus.UNAUTHORIZED)
    public Map<String, Object> handleAuth(AuthenticationException e) {
        return Map.of("code", 401, "message", "用户名或密码错误");
    }
}

七、Token 过滤器 ​

java
@Component
@RequiredArgsConstructor
public class JwtAuthenticationTokenFilter extends OncePerRequestFilter {

    private final RedisTemplate<String, Object> redisTemplate;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        String header = request.getHeader("Authorization");
        if (!StringUtils.hasText(header) || !header.startsWith("Bearer ")) {
            // 没有 token 就放行，是否需要认证交给后面的授权规则判断
            filterChain.doFilter(request, response);
            return;
        }

        String userId;
        try {
            userId = JwtUtil.parseJWT(header.substring(7)).getSubject();
        } catch (JwtException | IllegalArgumentException e) {
            throw new UnauthorizedException("Token 非法或已过期");
        }

        String redisKey = "login:" + userId;
        LoginUser loginUser = (LoginUser) redisTemplate.opsForValue().get(redisKey);
        if (loginUser == null) {
            throw new UnauthorizedException("登录状态已失效，请重新登录");
        }

        // 滑动续期：每次访问刷新 Redis 中的过期时间
        redisTemplate.expire(redisKey, Duration.ofDays(7));

        UsernamePasswordAuthenticationToken authentication =
                new UsernamePasswordAuthenticationToken(loginUser, null, loginUser.getAuthorities());
        SecurityContextHolder.getContext().setAuthentication(authentication);

        filterChain.doFilter(request, response);
    }
}

注意第三个参数：认证通过时必须把 authorities 传进去，否则后续 @PreAuthorize 之类的注解拿不到权限。旧代码里传 null，只能说明「已认证」，无法做权限判断。

八、认证失败处理 ​

Token 过滤器抛出的异常不会自动变成 JSON，需要 AuthenticationEntryPoint 兜底：

java
@Component
public class AuthenticationEntryPointImpl implements AuthenticationEntryPoint {

    @Override
    public void commence(HttpServletRequest request,
                         HttpServletResponse response,
                         AuthenticationException authException) throws IOException {
        response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
        response.setContentType("application/json;charset=UTF-8");
        response.getWriter().write("{\"code\":401,\"message\":\"未登录或登录已过期\"}");
    }
}

如果希望过滤器里的异常也走这里，可以让 UnauthorizedException 继承 AuthenticationException；否则需要单独的 @RestControllerAdvice 处理。

九、几个注意点 ​

  • 密钥别硬编码，更不要用 eaa2025 这种短字符串，HS256 会直接拒绝；生产环境放配置中心或环境变量；
  • Redis 与 JWT 的过期时间要一致，否则会出现 token 还有效但缓存已失效的情况；
  • 登出就是删缓存：redisTemplate.delete("login:" + userId)，不用维护黑名单；
  • 放行路径要精确，permitAll 的范围一大，鉴权就形同虚设；
  • Spring Boot 3 的包名是 jakarta.servlet，从旧项目迁移时记得一起改；
  • 跨域配置里 allowCredentials(true) 不能和 allowedOrigins("*") 共用，要用 allowedOriginPatterns。

十、小结 ​

这套流程的核心只有两点：认证发生在登录时，授权发生在每次请求的过滤器里。把 UserDetailsService、PasswordEncoder、SecurityFilterChain 三件事配好，剩下的就是按业务补权限。旧教程里的 WebSecurityConfigurerAdapter 已经退出历史舞台，照抄之前先确认版本。
