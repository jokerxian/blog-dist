Java 并发与锁机制 ​

并发问题说到底只有三件事：原子性、可见性、有序性。锁是把这三件事重新收拢的手段。

一、synchronized 做了什么 ​

对象头与监视器 ​

synchronized 加在方法上，锁的是 this；加在静态方法上，锁的是 Class 对象。真正干活的是对象头里的 Mark Word 和操作系统提供的监视器。

java
public class Counter {
    private int value;

    public synchronized void increase() {
        value++;
    }

    public synchronized int get() {
        return value;
    }
}

value++ 本身不是原子操作，读、加、写三步之间都可能被切走。加锁之后，三步被包成一个整体。

锁升级 ​

偏向锁、轻量级锁、重量级锁是 JVM 对同一把锁的三种处理方式。竞争越激烈，升级越高。升级不可逆，所以不要指望一把已经膨胀的锁再变轻。

二、AQS 的骨架 ​

ReentrantLock、Semaphore、CountDownLatch 背后都是 AQS。它用一个 volatile int state 表示资源，用一个 CLH 变体队列挂住等待的线程。

java
public final void acquire(int arg) {
    if (!tryAcquire(arg) && acquireQueued(addWaiter(Node.EXCLUSIVE), arg)) {
        selfInterrupt();
    }
}

子类只需要实现 tryAcquire 与 tryRelease，排队、阻塞、唤醒这些脏活都由 AQS 接管。

三、选锁的经验 ​

  • 只保护几个变量：优先 synchronized，语义清楚，JVM 还会帮忙优化。
  • 需要超时、可中断、公平锁：用 ReentrantLock。
  • 读多写少：ReentrantReadWriteLock，或者直接换 StampedLock。
  • 无锁计数：AtomicInteger / LongAdder，高并发下后者更稳。

锁不是越多越好。临界区越小，争用越少；但边界切得太碎，正确性又难保证。真正的功夫在「切在哪里」。
