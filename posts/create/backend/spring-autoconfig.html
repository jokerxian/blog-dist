Spring Boot 自动装配 ​

自动装配不是魔法，只是把「读配置、判断条件、注册 Bean」这一套固定动作收进了框架里。

一、入口在哪 ​

三个注解叠在一起 ​

java
@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

@SpringBootApplication 由 @SpringBootConfiguration、@EnableAutoConfiguration、@ComponentScan 组成。真正引入自动配置的是 @EnableAutoConfiguration。

二、配置类从哪里来 ​

@EnableAutoConfiguration 通过 AutoConfigurationImportSelector 读取 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports，拿到一长串候选配置类。

候选类不会全部生效，还要过一遍条件注解。

条件装配 ​

java
@AutoConfiguration
@ConditionalOnClass(DataSource.class)
@ConditionalOnMissingBean(DataSource.class)
public class DataSourceAutoConfiguration {
    // ...
}
  • @ConditionalOnClass：类路径上有这个类才生效；
  • @ConditionalOnMissingBean：容器里没有同类 Bean 才补一个；
  • @ConditionalOnProperty：配置开关打开才生效。

三、排查自动配置 ​

启动时加上 --debug，控制台会打印 CONDITIONS EVALUATION REPORT，哪些配置生效、哪些被跳过、为什么跳过，一目了然。

理解了这一层，再遇到「为什么我的 Bean 没注入」，就不会只盯着 @Component 看了。
