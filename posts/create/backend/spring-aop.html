Spring AOP：用自定义注解做接口校验 ​

业务代码里总有些重复逻辑：校验 Token、记录耗时、打印入参。把它们复制到每个方法里，接口本身反而看不清了。AOP 解决的就是这类横切关注点。

一、AOP 是什么 ​

AOP（Aspect Oriented Programming，面向切面编程）把散落在各处的相同代码抽成独立模块，在不修改原方法的前提下增强它的行为。增强的方式是「通知」，也就是在方法执行的某个时机插入一段额外逻辑。

Spring AOP 基于动态代理实现：目标类有接口时用 JDK 代理，没有接口时用 CGLIB 生成子类。所以它只能增强容器管理的 Bean 的方法调用，字段访问和构造方法都不在范围内。

二、几个核心概念 ​

概念含义
切面（Aspect）横切关注点的模块化，通常是一个带 @Aspect 的类
连接点（JoinPoint）可以被拦截的点，Spring 中只支持方法
切点（Pointcut）用来定位连接点的表达式
通知（Advice）拦截到连接点后执行的代码，也叫增强
目标对象（Target）被代理的原始对象
织入（Weaving）把切面应用到目标对象的过程

切点决定「拦谁」，通知决定「拦到之后做什么」。

三、五种通知 ​

text
前置通知  @Before          方法执行前
返回通知  @AfterReturning  方法正常返回后
异常通知  @AfterThrowing   方法抛出异常后
后置通知  @After           方法结束后（无论成功失败）
环绕通知  @Around          包住整个方法，可自行决定是否执行

执行顺序大致是：

text
@Around 前半段 -> @Before -> 目标方法 -> @AfterReturning / @AfterThrowing -> @After -> @Around 后半段

@Around 最灵活，可以修改入参和返回值，但也最容易写错，能不用就不用。

四、实战：自定义注解校验 Token ​

目标很明确：给需要登录的接口加一个 @Token 注解，请求进来时由切面统一校验请求头里的 Token，业务方法里不再出现校验代码。

引入依赖 ​

xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-aop</artifactId>
</dependency>

这个 starter 已经包含 AspectJ 的织入能力，不需要额外配置。

定义注解 ​

java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface Token {
    /** 校验失败时的提示，可省略 */
    String desc() default "";
}

RUNTIME 是必须的，切面要在运行时通过反射读取它。

编写切面 ​

java
@Slf4j
@Aspect
@Component
public class TokenAspect {

    /** 以注解为切点：所有标注了 @Token 的方法 */
    @Pointcut("@annotation(com.example.demo.annotation.Token)")
    public void tokenPointcut() {
    }

    @Before("tokenPointcut()")
    public void checkToken(JoinPoint joinPoint) {
        ServletRequestAttributes attributes =
                (ServletRequestAttributes) RequestContextHolder.getRequestAttributes();
        if (attributes == null) {
            throw new IllegalStateException("当前不是 Web 请求上下文");
        }

        HttpServletRequest request = attributes.getRequest();
        String token = request.getHeader("Authorization");
        if (!TokenUtil.valid(token)) {
            log.warn("Token 校验失败：{}", joinPoint.getSignature().toShortString());
            throw new UnauthorizedException("Token 校验失败");
        }
    }
}

几个注解的作用：

  • @Aspect：声明这是一个切面；
  • @Pointcut：定义切点，这里用 @annotation 限定到注解标记的方法；
  • @Before：在目标方法之前执行；
  • @Component：把切面交给 Spring 管理，否则不会生效。

异常不要直接抛 RuntimeException，定义一个业务异常并用 @RestControllerAdvice 统一转成 401，前端才能正确处理。

在接口上使用 ​

java
@GetMapping("/hello")
@Token(desc = "需要登录的接口")
public String hello(String name) {
    return "Hello " + name;
}

常用切点表达式 ​

java
// 指定包下所有方法
@Pointcut("execution(* com.example.demo.service..*.*(..))")

// 标注了某个注解的方法
@Pointcut("@annotation(com.example.demo.annotation.Token)")

// 标注了某个注解的类里的所有方法
@Pointcut("@within(org.springframework.web.bind.annotation.RestController)")

execution 的写法是 返回值 包名.类名.方法名(参数)，.. 表示任意层级或任意参数，范围别放太宽，否则会把无关的 Bean 也代理进去。

五、容易踩的坑 ​

同类内部调用不生效。 代理是在 Bean 外部调用时起作用的，this.otherMethod() 不会经过代理，切面自然也不会执行。要么把方法拆到另一个 Bean，要么注入自身代理。

private 方法拦不住。 无论是 JDK 代理还是 CGLIB，都只能增强可被外部调用的方法。

多个切面要注意顺序。 用 @Order 控制，值越小越先进入。否则「日志切面」和「鉴权切面」谁先执行只能碰运气。

@Around 必须放行。 忘了调用 joinPoint.proceed()，目标方法就永远不执行；返回值和异常也要原样传递。

六、小结 ​

AOP 的价值在于把「与业务无关但每个接口都要做」的事情收拢到一处。自定义注解加切面的组合是最常见的落地方式：注解负责标记，切点负责定位，通知负责执行。用好了，业务代码会干净很多；用过头，调用链会变得难以追踪，边界要自己把握。
