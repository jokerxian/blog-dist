Docker 与 Docker Compose 部署指南 ​

网上不少 Docker 安装教程还停留在 docker-ce 17.03 和 docker-compose 独立二进制的年代。现在的做法已经变了几轮：仓库地址换了、Compose 变成了 CLI 插件、version 字段也被废弃。这篇按当前的方式重新整理一遍。

一、安装前准备 ​

如果机器上装过旧版本，先清掉，避免包冲突：

bash
sudo yum remove -y docker docker-client docker-client-latest docker-common \
  docker-latest docker-latest-logrotate docker-logrotate docker-engine

Ubuntu / Debian 对应的是：

bash
sudo apt remove -y docker docker-engine docker.io containerd runc

数据目录 /var/lib/docker 默认会保留，确认不需要旧数据后再手动删除。

二、安装 Docker Engine ​

CentOS / RHEL / Rocky / AlmaLinux ​

bash
# 安装仓库管理工具
sudo dnf -y install dnf-plugins-core

# 添加 Docker 官方仓库
sudo dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo

# 国内网络可换成阿里云镜像站
sudo sed -i 's+download.docker.com+mirrors.aliyun.com/docker-ce+' /etc/yum.repos.d/docker-ce.repo

sudo dnf makecache
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Ubuntu / Debian ​

bash
sudo apt update
sudo apt install -y ca-certificates curl gnupg

sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Debian 系统把两处 ubuntu 换成 debian 即可。国内网络同样可以把 download.docker.com 替换为 mirrors.aliyun.com/docker-ce。

测试环境的一键脚本 ​

只想快速起个环境时，用官方脚本最省事：

bash
curl -fsSL https://get.docker.com | sudo sh

注意它会安装最新稳定版，生产环境还是建议走仓库锁定版本。上面安装的四个包里，docker-compose-plugin 就是 Compose V2，不用再单独装。

三、启动与验证 ​

bash
# 启动并设置开机自启
sudo systemctl enable --now docker

# 查看服务状态
sudo systemctl status docker --no-pager

# 查看版本
docker version
docker info

# 跑一个容器确认整条链路正常
docker run --rm hello-world

默认只有 root 和 docker 组能操作 Docker。把当前用户加进去，之后就不用每条命令都带 sudo：

bash
sudo usermod -aG docker $USER
newgrp docker

newgrp 只对当前终端生效，重新登录后所有会话都会带上新组。

四、配置镜像加速与日志轮转 ​

国内拉取镜像慢，可以在 /etc/docker/daemon.json 里配置加速器。加速地址可以登录阿里云容器镜像服务控制台，在「镜像工具 → 镜像加速器」里获取自己的专属地址；也可以到 status.anye.xyz 查看各个公共加速器的实时可用状态，挑一个能用的填进去：

json
{
  "registry-mirrors": ["https://<你的专属加速地址>.mirror.aliyuncs.com"],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  }
}

改完重启生效：

bash
sudo systemctl daemon-reload
sudo systemctl restart docker
docker info | grep -A 3 "Registry Mirrors"

日志轮转也一并配上，否则容器跑久了，json-file 日志能把磁盘写满。公共加速器的可用性经常变化，失效时换一个源即可，不必怀疑安装步骤。

五、安装 Docker Compose ​

Compose V2 是 Docker CLI 的插件，命令是 docker compose（中间是空格）。用上面的仓库方式安装时已经包含，先确认：

bash
docker compose version

如果用的是脚本安装或精简系统里没有，手动装插件也很简单，放进 CLI 插件目录即可：

bash
sudo mkdir -p /usr/local/lib/docker/cli-plugins
sudo curl -SL https://github.com/docker/compose/releases/latest/download/docker-compose-linux-x86_64 \
  -o /usr/local/lib/docker/cli-plugins/docker-compose
sudo chmod +x /usr/local/lib/docker/cli-plugins/docker-compose

docker compose version

latest/download 会指向最新版本；需要固定版本就把路径换成 download/v2.x.y/docker-compose-linux-x86_64。旧教程里下载到 /usr/local/bin/docker-compose 的方式对应的是已停止维护的 V1，命令也还是带连字符的 docker-compose，新环境不必再这么做。

六、用 Compose 部署 MySQL ​

Compose 默认读取当前目录下的 compose.yaml 或 docker-compose.yml。新建一个目录，写入配置文件：

yaml
services:
  mysql:
    image: mysql:8.4
    container_name: mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:?请在 .env 中设置}
      TZ: Asia/Shanghai
    ports:
      - "3306:3306"
    volumes:
      - mysql-data:/var/lib/mysql

volumes:
  mysql-data:

几点说明：

  • 顶层的 version 字段在 Compose Spec 中已废弃，写了会有告警，直接省略；
  • 密码通过变量注入，同目录建一个 .env：
bash
MYSQL_ROOT_PASSWORD=ChangeMe_2026

.env 记得加进 .gitignore，别把密码提交进仓库。也可以直接用 docker compose --env-file 指定另一个文件。

  • restart: unless-stopped 表示随 Docker 启动，除非手动停过；
  • mysql-data 是命名卷，比绑定宿主机目录省心，不用处理 MySQL 的目录权限。

启动并检查：

bash
docker compose up -d
docker compose ps
docker compose logs -f mysql

看到 ready for connections 就说明启动完成。进容器执行 SQL：

bash
docker compose exec mysql mysql -uroot -p

七、常用命令 ​

bash
docker compose up -d          # 后台创建并启动
docker compose ps             # 查看本项目的容器
docker compose logs -f        # 持续查看日志
docker compose start          # 启动已存在的容器
docker compose stop           # 停止容器，不删除
docker compose restart        # 重启
docker compose exec mysql bash  # 进入容器
docker compose config         # 校验并输出最终配置（含变量替换结果）
docker compose down           # 删除容器与网络，保留数据卷
docker compose down -v        # 连数据卷一起删除，慎用

几个容易踩的点：

  • up -d 会自动创建网络并按依赖顺序启动，但不会等待服务真正可用；
  • down 默认保留命名卷，数据还在；只有 down -v 才会删卷，生产环境执行前务必确认；
  • 同一台机器跑多个项目时，记得给 container_name 和端口错开，或者干脆不写 container_name，让 Compose 自动加项目前缀；
  • 镜像尽量固定到具体版本（如 mysql:8.4），不要用 latest，否则某次 pull 可能直接改变运行行为。

八、小结 ​

整套流程其实只有三步：装好 Engine、确认 docker compose 可用、写好配置文件后 up -d。真正需要留意的是后面这些细节：镜像源、日志轮转、数据卷去留，以及别把密码写进仓库。

数据库端口 3306 如果不需要对外，建议把 ports 那行删掉或改成 127.0.0.1:3306:3306，只允许本机访问，再配合防火墙与安全组，暴露面会小很多。
