用 GitHub + PicGo 搭建自己的图床 ​

Typora 默认把图片存在本地，文章发到网上后图片自然就裂了。图床要解决的就是这件事：插入图片时自动上传，正文里只保留一个可公开访问的 URL。

一、为什么选 GitHub ​

按存放方式来分，常见的图床有三类：

类型代表特点
公共图床SM.MS、路过图床免注册或注册即用，但稳定性和长期性不由自己控制
代码托管平台GitHub、Gitee仓库即图床，可控、免费，缺点是国内直连慢
对象存储 / 云服务器阿里云 OSS、七牛云、自建速度快、可绑定域名，但按量计费

对学生和个人博客来说，GitHub 仓库是成本最低的选择：公开仓库免费、容量足够，配合 jsDelivr 的 CDN 还能缓解访问速度问题。Gitee 虽然国内快，但免费仓库对单文件大小和容量限制比较紧，不适合长期堆图。

二、新建一个公开仓库 ​

登录 GitHub，右上角 + → New repository，仓库名随意，例如 pic，可见性选 Public。

仓库必须公开，否则 jsDelivr 无法读取。私有仓库需要走带签名的私有资源地址，配置会麻烦很多。

三、生成访问令牌 ​

PicGo 需要凭令牌往仓库写文件。点击右上角头像 → Settings，左侧拉到最底，进入 Developer settings。

选择 Personal access tokens → Tokens (classic) → Generate new token (classic)。填写 Note 方便日后辨认，Expiration 按需选择，不建议选 No expiration，图床用多久就设多久。

权限只勾 repo 这一项即可，其余都不需要。

生成后令牌只显示一次，先复制到安全的地方。它等同于仓库的写入权限，不要写进代码或提交到公开仓库。

GitHub 现在也提供 Fine-grained tokens：可以选择单个仓库，并把权限收窄到 Contents: Read and write，比 classic token 更安全。只是配置项多一些，按需选择即可。

四、安装并配置 PicGo ​

PicGo 是一个跨平台的图床上传工具，拖入图片就能得到链接。

安装完成后，打开 图床设置 → GitHub。

这是新版的UI，如图配置 按下面几项填写：

配置项填写内容
图床配置名自定义，例如 github
仓库名用户名/仓库名，例如 jokerxian/pic
分支名main（GitHub 新建仓库的默认分支）
Token上一步生成的令牌
存储路径仓库内的目录，例如 pics/
自定义域名jsDelivr 地址，见下一节

存储路径有几个约定：放在根目录就留空；多级目录直接写 img/2026/ 这样的相对路径，前面不要加 /；目录不存在时 PicGo 会自动创建。建议路径末尾统一带上 /，否则 PicGo 会把本地文件名拼到路径后面，得到 pics20240709.png 这种结果。

五、用 jsDelivr 加速 ​

jsdelivr地址：https://cdn.jsdelivr.net

GitHub 的原始文件地址在国内访问经常很慢，jsDelivr 把仓库内容缓存到 CDN 边缘节点，读取速度会好很多。它的 GitHub 地址格式是固定的：

text
https://cdn.jsdelivr.net/gh/用户名/仓库名@分支/文件路径

@分支 在仓库默认分支时可以省略。对应到 PicGo 的「自定义域名」，填到仓库名为止即可，文件名由 PicGo 自动追加：

text
https://cdn.jsdelivr.net/gh/jokerxian/pic

如果图片要传到非默认分支，才需要写成 https://cdn.jsdelivr.net/gh/jokerxian/pic@test。

需要注意的是，jsDelivr 在国内的可用性这几年有波动，偶尔会出现解析失败或加载缓慢。遇到这种情况，可以先换成自定义域名直连仓库，或者搭一层自己的 CDN；图片本身在 GitHub 上，不会丢。

六、测试上传 ​

配置保存后，在 PicGo 里把图片拖进上传区，或在相册页点击上传。

上传成功后可以在相册里查看图片、复制 URL 或删除。建议点开链接确认一次，能正常显示再继续下一步。

七、接入 Typora ​

打开 Typora 的 偏好设置 → 图像：

  • 「插入图片时」选择 上传图片；
  • 「上传服务」选择 PicGo，并指定 PicGo.exe 的安装路径；
  • 按需勾选「对本地图片应用上述规则」和「对网络图片应用上述规则」。

之后在 Typora 里粘贴或拖入图片，就会自动上传并替换成网络链接。如果上传失败，先检查 PicGo 是否能独立上传，再排查 Typora 的路径是否选对。

另外，如果本机开着 Steam++、Watt Toolkit 这类会接管 GitHub 流量的加速工具，上传时可能会报证书或连接错误，临时关闭再试。

八、几个细节 ​

开启时间戳重命名。 在 PicGo 设置里打开后，同名图片不会互相覆盖，避免旧文章里的图被新图替换。

控制仓库体积。 GitHub 建议单个仓库保持在 1GB 以内、单文件不超过 100MB。图片多的仓库最好按年份或主题分目录，必要时再考虑压缩。

注意 CDN 缓存。 jsDelivr 会缓存资源，替换同名图片后短时间内可能仍显示旧图，换个文件名最省事。

PicGo 更新较慢。 如果遇到新系统兼容问题，可以试试它的活跃分支 PicList，配置项基本兼容，迁移成本很低。

九、小结 ​

整套流程只做一次：建公开仓库、生成只含 repo 权限的令牌、在 PicGo 里填好仓库和 jsDelivr 域名、最后让 Typora 调用 PicGo。之后写作时只需粘贴图片，剩下的交给工具。

真正需要留心的是安全与长期性：令牌别泄露、仓库别转私有、CDN 失效时知道去哪里改。图床不是一劳永逸的服务，但自己掌控数据，至少不会因为某个公共图床关停而丢图。
